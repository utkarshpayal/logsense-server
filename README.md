# ⚙️ LogSense Ingestion & AI Query Server

This is the backend server for the **LogSense** observability ecosystem. Built on Fastify and PostgreSQL, it handles user authentication, workspace project isolation, API key lifecycle management, high-throughput log ingestion, and the conversational AI query engine powered by Google Gemini and Groq.

---

## ✨ Features

- **High-Throughput Ingestion**: Supports bulk log ingestion from the SDK via `POST /logs/batch`. Features automatic gzip decompressing hook to optimize network bandwidth.
- **AI Query Engine**: Parses natural language requests (e.g. *"Which API errored most?"*) and generates safe, optimized SQL queries to fetch matching metrics from PostgreSQL. Uses a multi-model fallback chain (Gemini ↔ Groq).
- **SQL Safety & Validation**: Restricts dynamic queries generated by the AI to read-only `SELECT` statements, whitelists allowed database columns/tables, and strictly injects project context scope (`WHERE project_id = ...`) to prevent data leakage.
- **Workspace Scoping**: Provides structural isolation for multiple developer accounts, projects, and environment scopes (`development`, `staging`, `production`).
- **Authentication**: Secure token-based authentication using `@fastify/jwt` and password hashing with `bcrypt`.
- **Database Migrations**: Standalone migration runner to update schemas, manage constraints, and indexes.

---

## 🛠️ Technology Stack

- **Fastify**: High-performance, low-overhead Node.js web framework.
- **tsx**: Watch-mode typescript runner for fast development.
- **PostgreSQL**: Time-series log and application data storage.
- **Zod & Fastify Type Provider Zod**: End-to-end type safety for request validation and response serializers.
- **Google Gemini & Groq SDKs**: Dual-tier LLM integration for translating Natural Language to executable SQL.

## 🚀 Getting Started

### 📋 Prerequisites
- **Node.js**: `v18.x` or later (recommended `v20+`)
- **PostgreSQL**: An active instance (local or hosted)

### 🔧 Installation & Setup

1. **Clone the repository** and navigate to the server directory:
   ```bash
   cd logsense-server
   ```

2. **Install project dependencies**:
   ```bash
   npm install
   ```

3. **Configure Environment Variables**:
   Create a `.env` file in the root of the project:
   ```env
   PORT=5000
   NODE_ENV=development
   DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/logsense
   JWT_SECRET=your_jwt_secret_token_here
   JWT_EXPIRES_IN=7d
   GEMINI_API_KEY=your_gemini_api_key
   GROQ_API_KEY=your_groq_api_key
   ```
   *Note: An active PostgreSQL URL and AI API key are required for operations.*

4. **Run Schema Migrations**:
   Execute the migration script to configure database schemas and tables:
   ```bash
   npm run migrate
   ```

5. **Start the local development server**:
   ```bash
   npm run dev
   ```
   The backend server will spin up and start listening on port `5000`.

## 📖 API Documentation

### 🔒 Authentication
- `POST /auth/register` - Create a new developer account.
- `POST /auth/login` - Authenticate credentials and return JWT bearer token.

### 📁 Projects & Workspaces
- `GET /projects` - Retrieve list of projects associated with the account.
- `POST /projects` - Create a new project workspace.
- `DELETE /projects/:id` - Revoke and remove a project and its associated log data.

### 🔑 API Keys
- `GET /api-keys?projectId=...` - Retrieve API keys for a project.
- `POST /api-keys` - Generate a new environment-scoped API key.
- `PUT /api-keys/:id/status` - Toggle API key state (`active` vs `disabled`).
- `PUT /api-keys/:id/rotate` - Rotate secret key value.
- `DELETE /api-keys/:id` - Delete an API key, blocking its future log ingestion immediately.

### 📝 Logs & Ingestion
- `POST /logs/batch` - High-throughput ingestion API called by client SDK. Accepts gzip headers and list of log entries.
- `GET /logs` - Fetch list of logs for the project with support for paginating, full-text searches, level filters, service scopes, and environments.
- `GET /logs/:id` - Retrieve complete fields, hostname details, and metadata payload of a single log entry.
- `DELETE /logs/:id` - Remove individual log events.

### 📊 Dashboard Metrics
- `GET /dashboard/overview` - Fetch totals for logs, error rates, and average latencies.
- `GET /dashboard/timeline` - Retrieve log volume over time-series buckets.
- `GET /dashboard/levels` - Retrieve total logs grouped by severity levels.
- `GET /dashboard/services` - Get average latency and error rates grouped by service names.
- `GET /dashboard/errors` - Fetch the most recent error logs.

### 🤖 AI Queries
- `POST /projects/:projectId/ai/chat` - Query project logs in natural language. Returns the conversational answer, generated safe SQL, query duration details, and raw database rows.
